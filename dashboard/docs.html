Get started with ktServe

Build a standalone HTTP service, publish a directory, or run your existing Kotlin application on ktServe.

Build a Kotlin HTTP service

Add ktServe to a Kotlin/JVM app on JDK 21, or to a Kotlin Multiplatform source set targeting Linux x86-64, Linux ARM64 or Apple Silicon macOS.

Add the Gradle dependency

repositories { mavenCentral() }

dependencies {
    implementation("codes.draeger:ktserve:0.4.0")
}

Maven Central ↗

Register a JSON route

import codes.draeger.ktserve.json
import codes.draeger.ktserve.serve

fun main() = serve(port = 8080) {
    get("/status") { json(mapOf("status" to "ok")) }
}

Start your application, then check the response from another terminal.

curl -fsS http://127.0.0.1:8080/status

Serve a directory from the terminal

Download the native CLI preview for your platform. Each archive includes ktserve and a sample public/ directory. You can run it without a JVM or a build step.

Linux x86-64 ↓ Linux ARM64 ↓ Apple Silicon macOS ↓ Release notes and SHA-256 checksums ↗

The Apple Silicon preview uses an ad hoc signature. macOS may ask you to approve it on first launch. Apple’s first-launch guidance ↗

Extract and run

From your download directory, replace the Linux x86-64 filename below with the archive you downloaded.

mkdir -p ktserve-cli-preview
tar -xzf ktserve-cli-preview-0.1.1-linux-x86_64.tar.gz -C ktserve-cli-preview
cd ktserve-cli-preview
./ktserve serve ./public

Open the sample

Open http://127.0.0.1:8080/ or request the sample JSON file from a second terminal.

curl -fsS http://127.0.0.1:8080/api/status.json

Pass your own directory to serve when you are ready. Add --mount /assets ./assets to serve a second directory or --access-log to log requests. Restart the process to refresh the file snapshot.

Build from source

To build the HTTP CLI on Linux x86-64, clone the cli-preview branch and use JDK 21.

CLI source and build guide ↗ 
git clone --depth 1 --branch cli-preview \
  https://github.com/christian-draeger/ktserve.git ktserve-cli-source
cd ktserve-cli-source
./components/ktserve/gradlew \
  -p components/ktserve/experiments/cli/static \
  linkReleaseExecutableNative
cd components/ktserve/experiments/cli
./ktserve serve ./public

From Linux x86-64, add -Pbenchmark.targetArch=aarch64 to build for Linux ARM64. On Apple Silicon, build with full Xcode and -Pbenchmark.targetOs=macos.

Build with direct HTTPS

For TLS support, install libssl-dev on Debian or Ubuntu and build from the root of the preview checkout. This variant uses OpenSSL 3 and a PEM chain with its matching unencrypted key.

./components/ktserve/gradlew \
  -p components/ktserve/experiments/cli/static \
  -Pktserve.opensslRoot=/usr linkReleaseExecutableNative
cd components/ktserve/experiments/cli
PORT=8443 ./ktserve serve ./public \
  --tls-cert /path/to/fullchain.pem --tls-key /path/to/key.pem

Use https://localhost:8443/ with a certificate valid for that hostname and trusted by your client.

From the CLI source directory, ./ktserve run ./run/App.kt 8080 builds and starts a Kotlin application. On the preview branch, call staticFiles("public") inside serve { } to put assets and API routes on the same listener.

Use your existing framework

Try ktServe as the HTTP engine for an existing app. Both adapters have runnable examples in the source checkout.

Ktor

Pass the KtServe engine factory to embeddedServer and keep your Ktor application module. The adapter supports Linux Native and JVM HTTP/1.x.

Spring Boot WebFlux

Enable ktserve.enabled=true with the checkout starter on the JVM. Keep your reactive controllers and functional routes.

Run and deploy ktServe

The qualified production profile uses ktServe as a private HTTP/1.1 origin with one epoll worker on Ubuntu 24.04 Linux x86-64 or ARM64, behind Caddy TLS ingress.

Try a native download

Download the archive and checksum for your platform from the release. Verify the archive, extract it and run ./ktserve to start the bundled example. The executable needs no JVM.
