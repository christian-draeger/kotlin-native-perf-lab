Build a Kotlin HTTP service

Add ktServe to a Kotlin/JVM app on JDK 21, or to a Kotlin Multiplatform source set targeting Linux x86-64, Linux ARM64 or Apple Silicon macOS.

Add the Gradle dependency

repositories { mavenCentral() }

dependencies {
    implementation("codes.draeger:ktserve:0.4.0")
}

Maven Central ↗

Register a JSON route

import codes.draeger.ktserve.json
import codes.draeger.ktserve.serve

fun main() = serve(port = 8080) {
    get("/status") { json(mapOf("status" to "ok")) }
}

Start your application, then check the response from another terminal.

curl -fsS http://127.0.0.1:8080/status

Download from the terminal

Run this in an empty directory to create ./ktserve and the sample public/ folder.

curl -fsSL https://github.com/christian-draeger/ktserve/releases/download/cli-preview-0.1.2/ktserve-cli-preview-0.1.2-linux-x86_64.tar.gz | tar -xzf -

Run it

HTTP

./ktserve serve ./public

The server listens on 127.0.0.1:8080 by default.

HTTPS on Linux

With an HTTPS download, provide a PEM certificate chain and its matching unencrypted key. Keep the key outside the directory you serve.

Create a one-day localhost certificate

Generate a self-signed certificate for local testing in the extracted directory. The openssl command is available in Ubuntu’s openssl package.

openssl req -x509 -newkey ec \
  -pkeyopt ec_paramgen_curve:P-256 \
  -noenc -days 1 -subj /CN=localhost \
  -addext subjectAltName=DNS:localhost \
  -keyout localhost.key -out localhost.pem
PORT=8443 ./ktserve serve ./public \
  --tls-cert localhost.pem --tls-key localhost.key

Test it

Request the sample JSON file from a second terminal.

HTTP

curl -fsS http://127.0.0.1:8080/api/status.json

Or open the sample site in your browser. http://127.0.0.1:8080/ ↗

HTTPS

curl -fsS --cacert localhost.pem \
  https://localhost:8443/api/status.json

Run this from the extracted directory. --cacert trusts the localhost certificate for this request.

Pass your own directory to serve. Use --mount /assets ./assets to serve a second directory or --access-log to log requests. Restart the process to refresh the file snapshot.

Use your existing framework

Try ktServe as the HTTP engine for an existing app. Both adapters have runnable examples in the source checkout.

Ktor

Pass the KtServe engine factory to embeddedServer and keep your Ktor application module. The adapter supports Linux Native and JVM HTTP/1.x.

Run and deploy ktServe

The qualified production profile uses ktServe as a private HTTP/1.1 origin with one epoll worker on Ubuntu 24.04 Linux x86-64 or ARM64, behind Caddy TLS ingress.
