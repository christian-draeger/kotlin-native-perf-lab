Kotlin/Native + JVM

HTTP serving,
built in Kotlin.

ktServe gives Kotlin apps an HTTP server with a small routing API. It also plugs in beneath Ktor and Spring Boot WebFlux as a server engine.

One HTTP core.
Three transports.

ktServe keeps HTTP parsing, connection state, routing and body streaming in a shared Kotlin core. A small transport interface handles socket reads, writes and readiness on each platform.

Read the transport design ↗

Use the framework you know.

Pick ktServe for a new service, or keep your existing routing and handler APIs and select ktServe as the engine.

Kotlin/Native + JVM

Ktor

Select the ktServe engine in embeddedServer. Your Ktor application module keeps its routes, plugins and content negotiation. The engine runs on Linux Native and the JVM.

JVM example ↗ Engine guide ↗
JVM

Spring Boot WebFlux

Enable the ktServe starter to run a WebFlux app on the JVM with its reactive handler pipeline. Activation is explicit, so the same app can also run with Reactor Netty.

The performance lab.

How close can an idiomatic Kotlin server get to Rust/Axum? Our working target is at least 90% of Axum's throughput, with p99 latency and CPU cost within 10% at comparable successful load.
